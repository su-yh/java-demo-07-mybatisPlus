
mysql 支持的隔离级别值：
    READ-UNCOMMITTED
    READ-COMMITTED
    REPEATABLE-READ（MySQL 默认）
    SERIALIZABLE  （串行化）

1. READ-UNCOMMITTED（读未提交）
    含义：一个事务可以读取到另一个事务未提交的修改数据。
    特点：
        隔离级别最低，并发性能最高（几乎无锁阻塞）。
        会导致 脏读（读取到未提交的 “脏数据”，如果对方回滚，读取的数据无效）。
        实际业务中几乎不使用，因为数据一致性无法保证。
    示例：
        事务 A 修改了一条数据但未提交；
        事务 B 能立即看到事务 A 的修改结果；
        若事务 A 回滚，事务 B 读取的是 “无效数据”。
2. READ-COMMITTED（读已提交）
    含义：一个事务只能读取到另一个事务已提交的修改数据。
    特点：
        解决了 脏读 问题（只看已提交的数据）。
        但存在 不可重复读 问题（同一事务内两次读取同一数据，结果可能不同，因为中间被其他事务修改并提交了）。
        是大多数数据库的默认隔离级别（如 PostgreSQL、SQL Server），平衡了一致性和并发性能。
    示例：
        事务 A 第一次读取数据为 100；
        事务 B 修改数据为 200 并提交；
        事务 A 再次读取时，数据变为 200（前后读取结果不一致）。
3. REPEATABLE-READ（可重复读，MySQL 默认）
    含义：同一事务内多次读取同一数据，结果始终一致（不受其他事务提交的修改影响）。
    特点：
        解决了 不可重复读 问题（重复读取结果一致）。
        MySQL 的 InnoDB 引擎通过 MVCC（多版本并发控制） 实现，而非加锁，性能较好。
        理论上存在 幻读 问题（同一事务内，两次查询相同范围的数据，结果行数不同，因为其他事务插入了新数据），但 MySQL InnoDB 通过 间隙锁 实际避免了幻读。
    示例：
        事务 A 第一次读取 id=1 的数据为 100；
        事务 B 修改 id=1 的数据为 200 并提交；
        事务 A 再次读取 id=1 的数据，仍为 100（保持第一次读取的版本）。
4. SERIALIZABLE（串行化）
    含义：所有事务串行执行（一个接一个执行，而非并行），完全隔离。
    特点：
        隔离级别最高，数据一致性最强（避免脏读、不可重复读、幻读）。
        并发性能最差（会导致大量锁等待，甚至死锁），因为事务无法并行操作相同数据。
        适用于对数据一致性要求极高的场景（如金融核心交易）。
    示例：
        事务 A 操作 id=1 的数据时，事务 B 会被阻塞，直到事务 A 提交 / 回滚；
        事务 B 只能在事务 A 完成后，才能操作 id=1 的数据，避免任何并发冲突

查看隔离级别
SELECT @@global.transaction_isolation; -- 全局默认
SELECT @@transaction_isolation; -- 当前会话默认

临时修改全局隔离级别：
    -- 需要有相关的权限
    -- 这里修改，只会在服务重启前生效，重启后将会失效。
    -- 同时，mysql 如此修改事务隔离级别，所有的数据库都将使用该事务隔离级别，没法针对某个数据库使用此隔离级别。
    SET GLOBAL transaction_isolation = 'SERIALIZABLE';


事务隔离级别优先级：
    在我们通过客户端连接去使用事务时，优先使用的是连接客户端指定的隔离级别，如果未指定才会使用数据库服务端的隔离级别。
    在java springboot 项目中，通过是使用注解方式添加事务隔离，@DSTransactional | @Transactional
    注解（@DSTransactional） 没有提供参数让我们配置事务隔离级别，但是 @Transactional 有提供事务隔离级别的控制。
    另外在数据库连接配置时，也可以设置隔离级别。
    所以最终的优先级顺序为：
        注解@Transactional(isolation = Isolation.SERIALIZABLE) > 连接配置 > 服务端默认配置。
